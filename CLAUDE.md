## High‑Level Architecture

The codebase follows a **feature‑first** organization, mirroring the screens/routes defined in the `app/` directory (Expo Router). Each top‑level feature lives under `src/features/` and is split into three logical layers:

1. **API Layer (`src/features/*/api`)** – thin wrappers around remote calls (Supabase, custom back‑ends). They expose async functions used by the store layer.
2. **Store/Model Layer (`src/features/*/model`)** – state management built with **Zustand** and **React‑Query**. Stores encapsulate business logic, caching, and side‑effects such as syncing.
3. **UI Layer (`src/features/*/ui`)** – React components tied to the corresponding route screens. UI components are kept presentational; navigation is handled by Expo Router files under `app/`.

### Core Directories
- **`app/`** – Expo Router entry point. Each folder under `app/` corresponds to a screen group (e.g., `app/(auth)`, `app/(settings)`). Layout files provide shared navigation UI.
- **`src/entities/`** – Domain entities (Account, User, Vault) with TypeScript types and minimal helpers. Used across features to enforce a consistent data model.
- **`src/shared/`** – Generic utilities:
  - `config/` – Theme and global settings context.
  - `hooks/` – Reusable React hooks (e.g., drag‑reorder).
  - `lib/` – Low‑level services:
    - `database/` – SQLite wrapper.
    - `encryption.ts` – Crypto utilities.
    - `i18n/` – Internationalization setup.
    - `supabase/` – Supabase client singleton.
    - `sync/` – Sync engine for offline‑first behaviour.
  - `ui/` – Atom‑level UI primitives (AppBar, Button, Icon, etc.) used throughout the app.
  - `utils/` – Small helper functions for error handling and result types.
- **`src/widgets/`** – Higher‑order UI components that compose the shared primitives (e.g., floating action buttons, skeleton loaders).

### State Management
- **Zustand** (`src/shared/config/settingsStore.ts`, feature‑specific stores) holds global mutable state such as theme, user preferences, and security settings.
- **React Query** (`src/features/*/model/*Store.ts`) drives server‑state fetching, caching, and background refetching for API data.
- **Sync Engine** (`src/shared/lib/sync/syncEngine.ts`) orchestrates offline queues and conflict resolution between SQLite and Supabase.

### Navigation
- Expo Router maps file‑system routes directly to screens. Nested groups (e.g., `(auth)`, `(settings)`) enable tab‑style navigation and shared layouts.
- Each screen component lives in `app/(feature)/<screen>.tsx` and typically consumes a corresponding store from `src/features/*/model`.

## Project‑Specific Rules & Tips
- **Expo version** – The project targets **Expo SDK v56**. Consult the versioned docs at https://docs.expo.dev/versions/v56.0.0/ for any breaking API changes.
- **Authentication** – Auth flows are implemented in `src/features/auth`. The `authStore` manages JWT and secure storage via `expo-secure-store` and device pin handling (`expo-local-authentication`).
- **Vault feature** – Handles encrypted data storage. Encryption utilities are in `src/shared/lib/encryption.ts`; syncing is coordinated by `syncEngine`.
- **Testing** – Tests are located alongside components (e.g., `Component.test.tsx`). Use the `@testing-library/react-native` utilities that come with Expo.
- **Internationalization** – The i18n setup lives in `src/shared/lib/i18n`. Add new locales by extending `locales/*.ts` and updating the language selector UI.
- **Code Generation** – Follow the existing folder conventions when adding new features: create an `api`, `model`, and `ui` subfolder under `src/features/<newFeature>` and add a matching route file under `app/`.
